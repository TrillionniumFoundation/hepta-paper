## 当前具体缺口 B：读取总时限及 fresh now

`admission.rs:169–173` 只对 socket 设置一次 `SO_RCVTIMEO`；`frame.rs:54–56,79–82` 使用 `read_exact`。每次 read 都在超时内返回少量字节时，整个 header+payload 可远超 `read_timeout_ms`。这与 ADR-0002:24 的 hard byte/time limit 和 runtime/CODEX_AND_BROKER.md:150 的 bounded deadlines 有差距。现 frame 的1MiB cap只限制字节，并不是总 elapsed time。

`server.rs:363–364` 在读取之前采集 now/trust snapshot，`:387–394` 传这个 now；`service.rs:38–51` 把同一值交给读取后的 capability 校验及 journal reserve。因此一个读入时尚有效、读完时已过期的实际签名请求仍可通过这些时间比较。journal `store.rs:217–224` 也在 `BEGIN IMMEDIATE` 等待之前检查 supplied now，另有 SQLite busy wait 的时间边界；不能仅改 read timeout 后声称所有事务临界时间问题闭合。

最小下一片：socket-specific reader 用单一 `Instant` deadline 覆盖 header+payload，每次系统读取前设置剩余时间，收到部分数据/EINTR之后不重置 deadline；保持 generic frame API 与 canonical字节不变。服务应在有界读取结束后从真实 `BrokerClockV1` 新采 now 并取当前 trust snapshot，再验签与 reserve；内部拆分真实 peer/frame capture 与 authenticate/reserve，保留已有 public 显式 now API，不使用构造的时间冒充生产实时时钟。对 transaction busy wait 的 freshness 若不在本片处理须明确保留。

最低真实连接测试：UnixStream pair/实际 listener 持续在单次timeout以内输送小片段，总时限仍及时拒绝且 nonce/operation均零；header与payload共用预算；完整合法signed请求按旧hash成功；读取期间真实已过期signed capability拒绝；读取后 clock/trust失败不会reserve；client EOF/partial read仍保留原错误分类。用拥有的测试线程/子进程并设置外层上限、join/cleanup，不把短连接空probe当生产资格。
