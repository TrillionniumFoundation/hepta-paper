## Finding A — worker failure can leave the service accepting and can detach other workers

1. `listener.rs:184–186` makes the listener nonblocking. `server.rs:239–280` polls only shutdown and the acceptance cap; it does not observe worker completion.
2. `run` retains the receiver Arc at `server.rs:216`. Consequently all worker exits do not disconnect the queue while the accept loop is alive. With the normal large cap, it can queue clients up to capacity then keep serving Busy indefinitely.
3. Several worker errors exit without setting the stop flag: queue poison (`352–355`), socket configuration (`363`), after-read clock error (`380`), journal errors (`456–468,471–473`), and post-lock clock error (`503`, added at 730dceeb). A worker panic likewise reaches no stop signal.
4. `server.rs:285–295` returns on the first joined Err or panic. Remaining JoinHandles drop, detaching still-active workers. Additional run-level `?` after the first spawn (`219` on opening later journals, `242` on accept, `254` on busy-response timeout configuration) skip owned cleanup altogether.
5. Existing clock integration uses `maximum_connections: 1` (`tests/admission_deadline.rs:243–249`) and so reaches join without testing automatic stop from worker failure (`:609–626`). It does not cover the normal-cap hang.

A source-derived minimal regression uses one worker, cap well above one, a genuine complete signed frame, and an owned injected clock failure after startup. No external shutdown should be needed for a bounded completion; current code stalls in the acceptance loop. The test must retain an emergency cleanup handle on assertion failure.

A second regression needs two real accepted requests and two workers: one reaches a controlled test dispatcher after its real reservation and waits cooperatively on cancellation; the other returns an owned clock fault. Check that cancellation reaches the live dispatcher, a completion/Drop witness exists before `run` returns, no third request is dispatched, and the original typed error is returned. This test dispatcher is a lifecycle witness, never production authority. Separately test worker panic and normal cap drain: a normal worker completion must not cancel another active dispatcher.

Minimal production fix: a private worker exit guard signals cancellation on Err/unwind but is disarmed on normal completion; from first worker creation onward every run path converges on one cleanup section. Record the first observed error, close the queue, join every owned worker, attempt exact listener shutdown, then return. Use `thread::Builder::spawn` if handling thread-resource failure as Result rather than a panic; adding a public WorkerSpawn error variant requires an exhaustive-match compatibility note. Keep normal acceptance-cap behavior as drain, not cancellation. This cannot promise termination of an arbitrary dispatcher that ignores cancellation, and must not kill threads or auto-release journal dispositions.

## Finding B — live cgroup owner can modify or remove a replacement directory

`CgroupV2OperationV1` stores only path/policy/fixture state/cleaned (`hepta-cgroup-containment/src/lib.rs:143–149`), with no retained directory FD or saved identity. `attach_pid` writes joined path controls (`228–246`), and cleanup writes cgroup.kill and removes joined paths (`260–289`). The control open (`376–386`) follows pathname resolution. `directory_identity` (`215–224`) captures whatever is currently at the path rather than checking against an originally retained owner. `recover_existing` checks the expected metadata once (`180–211`) but the returned live object loses that expected identity.

Deterministic, unprivileged, source-derived reproduction: create a LocalFixture operation; rename its directory to a held sibling; create a second LocalFixture operation at the original name; call the first object's attach or cleanup. The first object now writes/removes the second object's controls and directory. This requires no tight race. Fixture controls do not kill real processes, so it is a safe future regression. The real dispatch caller has create → durable binding → blocked-child attachment → later cleanup, so this is an actual production-source path rather than an unused helper. It is not proof of a malicious production mount/principal fixture having been executed.

Minimal safe follow-up: retain actual hierarchy and operation directory descriptors/identity; perform control opens and cleanup relative to those descriptors without following substituted controls; refuse path-identity drift without touching a replacement. Preserve expected identity through recover_existing and ensure Drop cannot retry cleanup against an adopted replacement. Before/after metadata comparisons alone do not close a concurrent pathname swap. Retain persisted recovery records on cleanup uncertainty. This is a distinct follow-up from the worker slice.

## Additional qualification limitation, not an executed production exploit

`CgroupV2PolicyV1::validate` (`lib.rs:102–118`) checks canonical prefix `/sys/fs/cgroup`, existence of two named files, and that `/proc/filesystems` advertises cgroup2. That establishes filesystem support, not that the selected actual directory is on a cgroup2 mount. Old code parsed the longest mountinfo match (`old cgroup.rs:299–330`), but had unbounded text reads and no retained descriptor anchoring. A safe producer should use a real retained directory and kernel filesystem type verification, plus controller/authority checks; do not revive the old text parser as proof or claim a fake `/tmp` hierarchy qualified. No privileges, mounts, or real cgroup files were modified in this audit.

1. Repair owned worker stop/join lifecycle with actual Unix/real-journal tests; preserve successful response and journal bytes.
