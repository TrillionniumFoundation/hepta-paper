# 旧 campaign-writer 分支核对

对比旧 all-gap ref `fab2458e98c4021baf194ae86155f95e3c3c9b3f` 与当前 `c5c08fbe3c1e469171126ba09c4c47c6d48a63c4`。[源文件/调用证据](hepta-campaign-writer-branch-review-20260922.json)。本轮只读，没有运行旧测试或迁移实际数据库。

旧 schema.rs/store.rs/types.rs 不是当前库中三个同名模块的遗漏：其数据库 application_id=1213224753、user_version=25、writer_authority 无expiry，而当前writer application_id=1213219671、schema=1、writer_lease有expiry。旧NodeState ready/claimed/prepared/completed与当前claimed/prepared/integrated等状态、claims字段、CPU/GPU资源、事件payload/hash规则均不同。它们也不等于原Node业务数据库schema。

旧public open(path,uid)直接打开本地writer；旧 WriterAuthorityV1 是调用者提供generation/token，acquire_writer以更高generation替换，无签名cutover输入。当前生产路径 service::production 调用 open_for_cutover，要求VerifiedWriterCutoverV1和数据库preimage，再检查lease；本地workflow通过create_local/open_local维持明确local模式。不能把旧acquire_writer接进当前生产路径来绕过cutover。

旧真实库外消费者在control-plane的local author slice及其同文件fixture测试；没有发现该旧slice在其他Rust文件消费者。当前production.rs、workflow.rs和独立local_vertical测试有实际writer消费者，但协议已改变，未逐一证明旧每个state-transition的等价迁移。旧五个store单测的存在不等于已执行/已独立验收。

共有功能包括claim/heartbeat/prepared/integrate、pre-provider失败和ambiguous保留、backup/restore；旧ready-node/add_node/recover_expired_claims及旧FaultPointV1不是当前同名接口。当前local recovery/control log/workflow恢复承担其他路径，不能仅按功能标签宣布全量语义等价。

处理结论：保留旧分支，不直接cherry-pick这三文件，不把同名CampaignWriterStoreV1/NodeClaimV1认定兼容。若旧v25状态或旧调用者实际部署，仍需其真实状态清单、单独适配/迁移/rollback与重放证据。当前独立writer-transfer/soak和完整持久resource dispatch仍未闭合；源码有更多函数不构成Node可退役依据。
