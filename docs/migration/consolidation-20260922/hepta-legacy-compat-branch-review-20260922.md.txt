# 旧 legacy-compat 分支核对

比对旧 all-gap 分支 `fab2458e98c4021baf194ae86155f95e3c3c9b3f` 和当前 `c5c08fbe3c1e469171126ba09c4c47c6d48a63c4`。文件身份和真实引用见 [JSON](hepta-legacy-compat-branch-review-20260922.json)。本轮只读，没有运行或宣称旧测试通过。

旧 `hepta-legacy-compat` 的 encoder 按 UTF-8 字节排序、serde_json number.to_string 编码、长度前缀 HeptaLegacyStableJsonV1 哈希。其库外 Rust 代码消费者是旧 control-plane 的 LocalSlicePlanV1/run_local_author_slice 路径；其执行测试在同一 lib 的 fixture 中。没有发现该旧 local slice 在其他 Rust 文件的消费者。不能把旧 encoder 的历史 Node 标注当作实际 Node oracle 证据。

当前 `hepta-compatibility` 保留同一 draft encoder/hash 的核心规则，并增加 16 MiB / 256 层限制；不是旧公开类型和错误的别名，也不是无条件字节/接口等价认证。旧 CLI 输出两行（draft JSON 和 draft hash），当前 hepta-legacy-stable-json-v1 默认输出 production JSON，显式 --rust-draft-v1 仅输出 draft JSON；命令名、限额、输出协议不同。旧命令若实际部署仍需显式迁移，不能静默用当前 CLI 代换。

当前实际历史 Node 契约在 hepta-legacy-compatibility 的 production.rs：冻结 ICU/CLDR profile、Ryu-JS 数字格式、原始 UTF-16/重复键/插入序解析，以及直接导入 workflow-kernel/record-hash.mjs 的 oracle。公开 legacy/draft API 保留旧语义，production API 明确分离；另一个 legacy-compatibility draft 对浮点 normalization 不同，不能按同名推断所有 draft hash 可互换。

当前 source tests 包括实际 Node differential oracle，但本审阅没有重跑。未配对 surrogate 的对象 key 被显式拒绝，其他历史 locale/profile、独立 263 文件重放与真正部署消费者仍需额外证明。本报告不等于所有历史数据/接口均已替代或 Node 可退役，也不删除或合并旧分支。
