# Native state backup deployment root

The native command adds the native `--root PATH` extension to `hepta-state-backup`, using the same option spelling as `hepta-runtime-image-reproducibility`. It addresses a concrete deployment failure: the previous binary always found the state database manifest through its compile-time source checkout, even after the executable was copied to another installation.

`native_workspace::resolve_native_workspace_root_v1` resolves an explicitly selected deployment root before the caller's legacy default. Relative roots resolve against the real working directory with POSIX lexical path semantics. The helper does not inspect the environment, create directories, follow symbolic links, read credentials or open manifests. The existing state-backup manifest reader remains responsible for bounded no-follow opens, exact held file identity, UTF-8/duplicate-member validation, and a final currentness check.

Ordinary frontends obtain missing defaults through `resolve_native_command_workspace_root_v1` and `current_native_command_workspace_root_v1`. An explicit typed root precedes a nonempty `HEPTA_PAPER_WORKSPACE_ROOT`. Without either, the executable must be physically inside the exact Cargo profile directory captured by `build.rs` (or its `deps` directory), or be an allowed frontend in the actual `ROOT/bin` layout. A directory merely named `debug` or `deps`, the caller's working directory, and an old compilation checkout are insufficient for a copied executable. Unknown copied layouts fail with `native_workspace_root_required` and require explicit configuration.

The `ROOT/bin` layout requires actual nonsymlink `paper-core`, `paper-core/bin` and `paper-core/config` directories and a regular, single-link `package.json` whose name is `hepta-paper-workspace`. The fixed executable-name allowlist lives in `native_workspace.rs`. Its package reader is shared with retirement package-version inspection: a no-follow, nonblocking held file descriptor limits input to 64 KiB and checks identity, length, permissions and timestamps before and after reading and against the named file. FIFOs, symbolic links, hardlinks, oversized files and invalid JSON cannot supply this marker. These observations select a path and establish cooperative read consistency; they grant no release, submission, activation or retirement authority. Each consumer still validates its own retained inputs.

For state backup, the selected root supplies `paper-core/config/autonomous-research-state-databases.v1.json`; its sibling `hepta-paper-runtime/native-runtime` supplies the default runtime. `--runtime-root` still wins over `HEPTA_PAPER_RUNTIME_ROOT`, which still wins over that default. Explicit authority configuration and bundle paths retain their original current-directory resolution. The command does not rewrite absolute pins inside a deployment authority configuration.

`--root PATH` and `--root=PATH` are equivalent. Missing/empty values and duplicates fail with the existing strict-parser error family. An explicit missing, unsafe, or refused root never falls back to the build checkout. The original help text remains unchanged. The deployment extension is documented here rather than changing the byte-for-byte original help contract. The original Node command rejects this newly added option; that acceptance difference is an explicit native extension and is not presented as original-input parity.

The relocated-binary test copies the actual executable to an independent temporary installation, changes its working directory, and provides an independent deployment workspace. Its manifest is materially different from the build checkout's canonical manifest. Its runtime is moved to the deployment workspace's sibling default. The process must return the actual deployed manifest/inventory hash; reading either the build checkout's manifest or the original runtime path fails the test. Additional process cases exercise relative/inline roots, environment and explicit runtime precedence, strict parsing, missing roots, and symbolic-link refusal. No authority subprocess is invoked by these status cases.

Other production callers reuse the same workspace selector for missing defaults while retaining their own explicit runtime/database paths and protected-root rules. Standalone and flat native commands resolve explicit relative paths against the real caller directory. Ordinary `operator store` retains the incumbent wrapper's child working directory: relative runtime configuration resolves against the selected frontend workspace, while an absolute runtime remains independently selectable. Runtime selection does not authenticate a workspace or grant authority.

The copied-ELF checks in `paper-core/tests/native-workspace-default-root.test.mjs` cover actual deployment defaults, a distant caller and decoy checkout, the real external Cargo target, typed/environment precedence, ordinary relative-runtime Node differential behavior, independent runtime/database selection, standalone consumers, and bounded package/timezone FIFO refusal. They are source and local process checks. They do not create an installation package, qualify the production host, or establish Node retirement acceptance.

The helpers are exported by the service library and consumed by the existing frontend and service owners. `tests/state_backup_relocated_binary.rs` exercises the actual copied backup executable; the original CLI parity targets retain their argument/default behavior checks. The implementation and executable tests are the source for accepted names, layout rules and observed results.
